# 从真机验证到提交审核

照着往下做就行。分两部分：先在自己手机上验证，再走上架流程。

前提：手机 iOS 17 或更新（`IPHONEOS_DEPLOYMENT_TARGET = 17.0`）。签名已经配好了，
Team `3Z47RGMC36`，Bundle ID `com.ryanzou.thrive`，不用再动。

---

# 第一部分：装到自己手机上

## 1. 连线并选中你的手机

数据线连上 iPhone，手机上如果弹「信任此电脑？」点信任。

回到 Xcode，窗口顶部中间那个设备选择器（写着 iPhone 17 Pro 之类的），
点开，在最上面的 **iOS Device** 分组里选你自己的手机。

## 2. 按 ⌘R

第一次会编译一两分钟，然后自动装到手机上。

**如果报 "Unable to install"**：手机没解锁，或者没点信任。解锁手机再来一次。

## 3. 手机上信任开发者

第一次装会提示「不受信任的开发者」，App 图标点不开。

手机上：**设置 → 通用 → VPN与设备管理 → 开发者 App → 点你的账号 → 信任**。

回桌面点开 Thrive。

> 免费账号签的 App 7 天过期，你是付费账号，一年有效，不用反复重装。

# 第三部分：上架流程

验证都过了再往下走。

## 1. 把仓库设为 public，再开 GitHub Pages（一次性）

Apple 强制要求隐私政策网址。私有仓库开 Pages 需要付费方案，所以先公开仓库。

**先公开**：仓库 → Settings → General → 拉到最底部 Danger Zone →
Change repository visibility → Make public → 按提示输入仓库名确认。

**再开 Pages**：Settings → Pages → Source 选 `Deploy from a branch`
→ 分支选 `main`、目录选 `/docs` → Save。

等一两分钟，确认这四个地址都能打开：

- https://ryanzou55.github.io/Thrive/
- https://ryanzou55.github.io/Thrive/privacy-policy/
- https://ryanzou55.github.io/Thrive/en/
- https://ryanzou55.github.io/Thrive/privacy-policy-en/

## 2. 在 App Store Connect 建 App

[appstoreconnect.apple.com](https://appstoreconnect.apple.com) → 我的 App → `+` → 新建 App

| 字段 | 填 |
|------|-----|
| 平台 | iOS |
| 名称 | Thrive 植物生长记录 |
| 主要语言 | 简体中文 |
| 套装 ID | 选 `com.ryanzou.thrive`（已经注册好了） |
| SKU | `thrive-ios-001` |
| 用户访问权限 | 完全访问权限 |

## 3. 上传构建版本

Xcode 菜单 **Product → Archive**（设备选择器要选 "Any iOS Device"，不能选模拟器）。

打包完 Organizer 会自动弹出 → 选中刚才那个 archive → **Distribute App**
→ App Store Connect → Upload → 一路下一步。

传完等 10～30 分钟，App Store Connect 里才会出现这个版本（Apple 要处理）。

## 4. 填资料

照抄 [metadata.md](metadata.md)。里面已经按中英两份分好了，字数都核过。

先填简体中文那份，然后在页面左上角语言下拉里 **添加 English**，填英文那份。
截图按尺寸槽位分目录存放，传哪套对应哪个槽位见 [metadata.md](metadata.md) 的「截图」一节
——传错槽位会直接报尺寸错误。

**App 隐私**问卷：全选「不收集数据」。Thrive 确实没有任何网络请求。

**年龄分级**：所有问题都选「无」，结果是 4+。

## 4b. 三处最容易找不到的必填项

提交时报 "You must complete the Contact Information section" 之类，
都是这几处没填。注意它们**分散在三个不同页面**：

| 要填的 | 在哪 | 填什么 |
|---|---|---|
| **Copyright** | 左侧 General → **App Information** | `2026 Ryan Zou`（年份 + 权利人姓名，不加 © 不加网址） |
| **Contact Information** | 版本页面（1.0 Prepare for Submission）拉到底 → **App Review Information** 里面 | 你的姓、名、电话、邮箱。给审核员联系用，不公开 |
| **App Privacy** | 左侧 General → **App Privacy** | 点 Get Started → 选「不收集数据」 |

App Privacy 那一项填完要点 **Publish** 才算生效，只保存不发布仍然会拦住提交。

「Sign-In Information」（是否需要登录账号）保持不勾——本 App 无需登录。

## 5. 提交审核

版本页面右上角 **提交以供审核**。

审核一般 1～3 天。被拒了把拒绝理由发我。

# 第四部分：以后发更新

首次上架才需要第三部分。之后每发一版，只走这五步。

## 1. 先拿真机的老数据验一遍 ⚠️ 最容易翻车的一步

**别删手机上的旧版本**，直接 ⌘R 覆盖装上去，然后把新功能和改过的界面都点一遍。

只要这一版动过 `@Model` 里的字段（`Plant` / `GrowthEntry` / `CareRecord`），这一步就不能省：
SwiftData 的轻量迁移只加列、不给已有的行回填默认值，所以**新增的属性必须是可选的**，
非可选的话老库升上来读到 nil 会直接崩。

这类崩溃全新安装 100% 测不出来，而且往往不是启动即崩，是点进某个读到新字段的
页面才崩。所以"能启动"不算验过，得把那个页面点开。

## 2. 改版本号

Xcode → 项目 `Thrive` → TARGETS → **General** → Identity：

- **Version**：必须比已上架的高（1.0 → 1.1 或 1.0.1）
- **Build**：同一个 Version 下必须递增。传上去就永久占用，删掉也不能重用

## 3. 打包上传

跟第三部分第 3 步一样：设备选 **Any iOS Device** → **Product → Archive**
→ Organizer → **Distribute App** → App Store Connect → Upload。

传完等 10～30 分钟，后台才会出现这个构建。

## 4. 在 ASC 建新版本

我的 App → Thrive → 左栏顶部「**+ 版本或平台**」→ iOS App → 填新版本号。

要填的只有两样：

- **此版本的新功能** —— 更新独有的必填项，中英两份都要写，文案见 [metadata.md](metadata.md)
- **构建版本** —— 点 `+` 选刚传上去的那个

隐私问卷、年龄分级、Copyright、SKU、类别、Pages 网址全部沿用，**不要动**。
截图只在界面有明显变化时才需要重传。

## 5. 提交

右上角 **提交以供审核**。更新的审核一般比首次快，通常一天内。

「版本发布」建议选**手动发布**，过审后自己挑时间上架。
